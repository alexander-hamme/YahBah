Its live evals (2026-10-25, after three prompt-tuning iterations) pass every gate in `whole_form`, and in `per_item` all but the curveball/behavioural gate (92.3%, one item); the verifier catches 90.5% against a 90% gate with 0% false rejection. **Round 2 (2026-11-07, also uncommitted)** resolved that entry's open decisions: a question about a named technology no fact mentions is not composed (`missing_fact`, so a required one ends `needs_answer`); an answer resting on absence from the profile's skills/bio/work/education lists is rejected unless a stored fact states it or declares the list complete (checks 8–10 on `quotes`/`absent`; the user adds `employment_history_complete` to `personal.yaml` when the work history is complete); recovery shows cited-but-unshown facts; and a held-out eval set (`YAHBAH_EVAL_SET=heldout`, never used to tune prompts) was added. Principle: code checks bookkeeping, models judge meaning. Commands and gates are in [development](development.md#live-evals-answer-engine-opt-in-live_llm). Migrations 0018 and 0019 are applied to the dev DB (2026-10-20); 0020 and the `known_answers` → `facts:` migration are user steps ([development](development.md#migrating-known_answers-to-facts-one-time-user-steps)), and until `personal.yaml` is migrated live runs end at MAP_ANSWERS as `internal_error`. A live run has reached discover (run `83a0efc2`, which exposed the misclassification), but no application has been submitted against a live site.
